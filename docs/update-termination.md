# 更新退出卡住 · 2026-09-08

## 证据与诊断

维护时用户桌面进程 PID 7701 仍在运行。先采集 1 秒线程样本，随后 SIGTERM 成功退出；未使用 SIGKILL，未触碰用户配置、身份或历史。

样本主线程位于 NSApplication.terminate → _shouldTerminate 的嵌套事件循环。旧 applicationShouldTerminate 返回 terminateLater，随后安排 MainActor Task 发送串门结束消息并回复退出。主线程在正在执行的 dispatch 回调内进入 AppKit 等待循环，依赖主线程任务完成的退出协议有停滞风险，与本次采样一致。磁盘包已是 2.7.2，不等于驻留进程已经完成重启。

另一个独立问题：旧更新器在原进程活着时调用 openApplication，可能只得到旧实例；立即退出并不能保证启动新版。

## 修复约定

- 菜单退出、内存退出、更新重启都先经 requestTermination 在正常事件循环中收尾；AppTerminationGate 防止重复请求和完成／超时竞争。
- 串门发送最长给 3 秒独立期限，超时取消任务并继续退出，不通过 terminateLater 等网络。
- applicationShouldTerminate 直接 terminateNow。系统注销或外部退出请求无需等待网络，好友离线状态由现有超时机制收敛。
- 更新安装成功后启动无终端的子进程，最多等待旧 PID 20 秒，消失后才执行 open -n；父进程仍在时绝不打开竞争实例，不杀死父进程。应用路径通过参数传递，不拼接 shell 代码。
- 检查／下载期间禁用再次检查和安装，成功后清除旧更新对象；重启助手创建失败时提示用户手动打开已安装版本。
- 原安装包身份、SHA-256、签名、目录恢复和网络错误检查保留。

## 菜单栏图标

使用已有 blobfish 角色 SVG，经既有清理与静态表情处理，21×18 pt，isTemplate=false，透明背景。无新增位图、无每帧重绘、不退回带底板的 AppIcon；资源加载失败保留文字入口。自检以图像 alpha 通道及角像素数值检查透明度，不做截图或人工视觉检查。

## 验证与界限

原生自检覆盖退出门控、真实子进程退出后才执行命令、旧进程仍在时超时不启动、中文／空格／shell 字符参数传递、单实例锁、目录恢复和透明图标。全套 97/97 通过；消息与设置外观代码检查仍为 8/8。

没有操作浏览器、发送真实好友消息或进行 GUI／视觉验收。旧版更新器的驻留代码不会被磁盘替换自动修好：从旧版升级若仍停住，须先退出旧进程再打开新版。
