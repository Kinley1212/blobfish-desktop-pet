# 水滴鱼项目经验与维护决策

更新日期：2026-08-12
当前发布基线：`v2.6.0`
当前开发分支：`main`

本文只记录已经从代码、测试或人工验证中确认的事实、约束和决策。尚未验证的猜测不得写成结论；每轮维护结束前应同步更新本文。

## 1. 维护规则

- 正式产品是 Swift/AppKit 原生应用，主代码位于 `native-appkit/Sources/BlobfishNative`。
- 仓库保留旧 Electron 实现用于资源、兼容逻辑及测试参考，不能在未核对引用关系时整目录删除。
- 修改必须从最新 `main` 建立 `codex/...` 分支，通过小步提交保留回滚点。
- 不用隐藏 UI、吞异常、写死结果或关闭校验来掩盖底层问题。
- 私钥、Token、证书和建箱密语不得写入仓库、日志或本文。
- 任何视觉检查、浏览器操作、耗时完整构建或非必要全量测试，开始前需取得维护者许可；一般修改授权不等于视觉检查授权。未获明确批准时只做源码、结构与自动化验证。

## 2. 角色与内容约束

### 水滴鱼

- 性格是委屈、疲惫、认命、轻微抱怨并偶尔关心。
- 台词通常较短，以「。」「……」收尾；避免过度卖萌、客服口吻、连续惊叹号及空泛鼓励。
- 常用深海、游不动、躺平、鱼鳍发酸等意象。
- 权威文字规范：`src/packs/languages/blobfish-zh-TW/style.json`。

### 小草团

- 项目正式名称是「小草团」。
- 性格是木讷、慢半拍、冷幽默、略委屈并偶尔关心。
- 使用风、根、叶、扎根、长大和开花等植物意象。
- 权威文字规范：`src/packs/languages/grass-buddy-zh-CN/style.json`。

### 语言包扩充

- 原始台词文件保持逐字不动；大批新增内容放在 `additions/state-variants.json`，并由各语言包 manifest 显式挂载，便于回退、统计与审查。
- 四个内建语言包目前覆盖同一组 71 个运行事件：水滴鱼繁中／英文分别为 381／201 条，小草团简中／英文分别为 398／210 条。
- 中英文同角色的新增台词须保持逐事件数量对齐；不同角色可以因既有内容差异而使用不同新增总数。
- 新台词只能使用 PhraseEngine 已支持、且事件调用方实际提供的上下文与条件。当前白名单为 `requires`、`batteryEquals`、`activeCountMin`、`remainingMin`、`remainingEquals`、`durationMinSeconds`、`lockedMinSeconds`、`clickCountMin`、`provider`、`weekdays`、`hourMin`、`hourMax`。

### 角色表情兼容性

- 水滴鱼继续使用 31 个外挂 face accessory；小草团只使用 `calm / happy / worried` 三个内嵌原生表情，不再叠加水滴鱼眼睛与脸部色块。
- 角色 manifest 的可选 `expressions` 声明原生表情模式、默认 face ID 与语义映射；face accessory 的可选 `characterPackIds` / `nativeExpression` 声明可用角色及其内嵌表情名称。旧 manifest 缺少这些字段时维持原有行为。
- 设置、临时台词表情、状态外观、对话硬编码表情与串门访客都必须先经角色兼容解析。旧水滴鱼 face ID 在小草团上只映射到三态，不兼容资源不得进入渲染层。
- 小草团三态直接切换角色 SVG 内标记了 `data-native-expression` 的脸部节点；catalog 中的 `face-grass-*` SVG 只提供完整 pack 资源契约，运行时不可再把它当普通 overlay 重复绘制。

## 3. 运动与屏幕边界

- `PetPanelController` 当前同时负责窗口、运动、拖动、惯性、边界、串门及部分展示状态，职责过多。
- 串门不再为移动模型添加独立暂停状态；访客鱼跟随主鱼的自动游动、拖动和惯性。
- 边界碰撞现在使用自己与访客鱼身体的联合移动区域；任务卡、气泡、性能面板等附着 UI 不参与物理碰撞。
- 主窗口现在是 `340×165` 的 artwork panel，只承载自己与访客角色；拖动、fling、自动上下/左右游动及四边碰撞继续只使用角色 artwork 的联合边界。
- 附着 UI 使用独立 overlay panel；它从编队当前所在 `NSScreen.visibleFrame` 计算完全在屏幕内、最大 `800×600` 的 scene canvas，再把角色屏幕坐标转换成 panel-local 坐标。角色位于任意屏幕精确边缘时都可向屏幕内部换位，不再受旧 `340×300` local canvas 限制，也避免在 4K 屏幕上重绘整块 visibleFrame。
- overlay panel 默认忽略鼠标，只在指针逐项命中未读角标、可点击消息气泡或闹钟按钮时接收事件；禁止用多个控件的外接矩形命中，否则透明间隙会形成 invisible wall。
- 靠近屏幕边缘时，附着 UI 应翻侧、压缩或换位，不能通过移动角色来迁就附着 UI。
- 拖动、fling、自动游动和屏幕碰撞必须由同一个运动状态模型控制，避免多份基线和坐标互相覆盖。
- hover、菜单、互动或拖动暂停时，角色的 `bobElapsed` 相位应冻结，显示振幅在约 0.2 秒内平滑收敛到静止位；恢复时平滑放大并从冻结相位续播。该过渡只改变 artwork layer，不得改写 panel origin、惯性速度或边界基线。
- hover 只暂停自主游动；当 `flingVelocity` 仍有效时，角色经过鼠标不得暂停，惯性衰减和边界反弹必须继续。菜单、明确互动和重新拖动仍有更高暂停优先级，使用户可以主动截停甩动中的角色。

## 4. 桌面显示模块

- `PetSceneLayoutCoordinator.layout` 是 scene overlay 的单一几何入口；timer、牵手状态、闹钟卡、任务堆栈、主人台词、双方消息气泡和性能面板必须一次性计算并共享 occupied 集合，绘制函数不得再自行决定位置。
- 倒数牌与牵手状态组成同一个水平 status group，中间保留固定间距；旧 `timer y=1` / `visit y=2` 重叠坐标已废弃。
- 闹钟提醒不再通过隐藏任务卡规避重叠；两者都交由统一 scene layout 放置。消息气泡在换到角色下方或侧面时，尾巴方向也必须随相对位置改变。
- 性能面板旧实现按整个 `340×300` 画布计算，曾导致离角色过远或与放大角色相交；禁止恢复这套定位方式。
- 单屏选择以角色与访客编队在各 `visibleFrame` 中的相交面积为准；没有相交时选最近屏幕。overlay scene canvas 围绕编队并被所选 `visibleFrame` 完整夹住，最大为 `800×600`；小屏幕则使用完整可见区。
- 物理限制：若可见区域小到所有启用卡片的总面积与尺寸本身无法无重叠容纳，任何布局都无法同时保证完整显示与零重叠；当前回归保证 `800×600` 及以上常规可见区域的四边组合。此时应新增明确的折叠/分页产品规则，不能用移动角色或静默裁切伪装解决。
- 性能面板已改为以角色边界为锚点，默认间距 6 pt；设置中的距离范围为 2–28 pt，串门时会评估与访客鱼的重叠并自动换侧。
- 建议显示层级：角色与饰品、鱼别气泡、任务/闹钟提醒、性能/牵手状态、未读与可点击控件。
- 好友消息使用独立气泡堆栈，不与普通角色台词的 `SpeechQueue` 共用替换规则。
- 好友气泡按说话者分别保留最新三条，owner 与 visitor 总计最多六条；新消息靠近各自说话者，旧消息上移并按各自新旧层级透明，最后 1 秒平滑淡出，每条消息有独立到期时间。
- 串门时，对方消息由访客鱼显示，自己发出的正文由自己的鱼显示。
- 好友气泡的 speaking presentation 与气泡停留时间必须解耦：owner / visitor 各自使用 token 和 1.2–4.0 秒短计时，旧 timer 不得清掉新状态，speaking 只叠加视觉 transform，不改写 idle / roam / working / waiting 的基础运动状态。

## 5. 鱼鱼传话与串门

- 身份私钥、收件权限和好友资料保存在 Keychain；不得改为普通明文配置。
- macOS `SecItem` 若未指定 `kSecUseDataProtectionKeychain`，默认仍使用 file-based Keychain；它按创建应用的代码签名 designated requirement 建立 ACL。ad-hoc 签名的 DR 绑定每次构建的 cdhash，因此重建后会被当作新应用并要求电脑密码。
- 启动时的身份读取必须使用 `LAContext.interactionNotAllowed = true`；若需授权，状态记为 `authorizationRequired`，不得自动弹窗、删除 item 或误建新身份。只有用户在设置页明确点击「授权读取现有身份」才允许交互式读取。
- 身份状态区分 `notConfigured / available / authorizationRequired / locked / corrupt / unavailable`。只有真正 `notConfigured` 可建立新身份；取消授权或钥匙串暂不可用时必须保留旧 item。
- 旧 ad-hoc `profile-v1` 无法安全静默交给正式签名版；未来迁移到 data-protection Keychain v2 时必须按「明确授权读旧项→验证→写新项→读回比对→最后删除旧项」交易执行，任一步失败都保留旧项。
- 设置页可以提供安全导入、有效性和指纹状态，但不默认展示私钥原文。重建身份必须二次确认。
- `FishMessengerService.poll()` 已加单飞保护，并依据本机历史中的 message ID 去重。
- 新收到的有效消息只有在本地历史保存成功后才向中转站确认；保存失败时回滚内存状态并保留远程投递，下轮重试。
- 未知发件人或鉴权失败的信封会失败关闭、上报错误并加入确认列表，避免中转站无限重投。
- 消息历史在运行内存和落盘时均限制为最新 500 条。
- 消息历史只允许读写当前用户所有、权限不宽于 `0600` 的普通文件；不安全或损坏的文件不得静默当成空历史。
- `createProfile`、`addContact`、发送、收取及已读变更会通知观察者，已打开的聊天 UI 可及时刷新。
- Messenger 在身份尚未建立时会保留 `start` 意图；身份创建成功后自动建立唯一轮询 Timer，不需要重启应用。
- `addContact` 必须拒绝与本机身份公钥相同的鱼鱼码，不允许把自己加为好友。
- 串门状态变更必须先检查 `blocked`、`muted` 和 `visitsEnabled`，不能先改变状态再由 UI 忽略。
- 配对、中转站、建箱密语、身份状态及鱼鱼码迁入设置页；右键菜单只保留「发消息…」和「历史消息」两个运行入口，不放身份或密钥设置。
- 历史窗口按联系人分组，收到消息靠左、发出消息靠右，不再承担普通文字发送；发消息使用独立单行小窗口，多个鱼友时必须明确选择收件人。
- 未读邮箱按最新未读消息定位联系人，桌面好友气泡用自带的 `contactID` 定位；历史窗口只在处于 key 状态时标记当前联系人已读。
- 发消息窗口是独立可取得键盘焦点的 NSWindow，但位置依附主鱼的 screen-space 角色边界；串门编队只参与避让和选屏，不进入角色的移动碰撞范围。窗口使用当前 `NSScreen.visibleFrame` 在上、下、右、左候选位中放置，支持负坐标与不同高度的多屏幕。
- 双击主鱼打开发消息窗口；单击反应延后到系统双击间隔确认后执行，第二次点击或累计移动达到 4 pt 会取消待执行的单击。消息气泡和未读邮箱仍只打开历史消息，不能改成发送入口。
- 发消息窗口隐藏时不得执行逐帧跟随计算；首次显示前先按最新 scene anchor 定位，可见期间才随游动、拖动及跨屏持续更新。
- 聊天窗口只在窗口处于 key 状态时标记当前联系人已读；不可因为窗口在后台存在就清掉未读。
- 发送过程中切换联系人或修改输入后，旧请求成功回调不得清空新草稿；只有联系人和原草稿都未变时才清空。
- 消息正文上限是 1,000 UTF-8 字节；聊天 UI 需显示超限字节数并禁止发送，不能只在加密层返回模糊错误。
- 已打开的聊天窗口必须在设置应用后更新 locale 和窗口标题，不能固定在首次创建时的语言。
- 消息停留时长存在 `FishFriendPreferences.messageDisplaySeconds`，旧 JSON 缺少字段时有效默认值为 20 秒。
- 限制：发送是「远程投递成功后记本地历史」；如果投递已成功而本地写盘失败，服务会显式报错，但无法原子撤回已投递的消息。若要完全解决需引入持久化 outbox 与投递状态协议，不应用自动重发掩盖。
- `send()` 返回真实的 `FishMessageRecord` 与 `historyPersisted`；桌面气泡必须沿用正式 message ID。远程已送达但本地历史失败时，UI 明确提示不要重发，不得把它当成纯网络失败。

## 6. 设置与右键菜单

- 设置窗口默认 `820×600`、最小 `760×540`；内容区和角色预览同步缩小，页面与卡片使用统一的紧凑间距。
- 最终密度、截断和键盘焦点顺序仍需通过人工视觉检查确认。
- 消息历史从设置页移出；设置只保留账户、安全、配对、停留时间、声音和串门权限。
- 设置窗口从隐藏状态重新打开时会刷新配置、时钟和 Messenger 草稿；窗口已经可见时再次唤起不得覆盖未保存编辑。
- 右键快捷开关修改游动、性能面板或开机启动后，只合并这四个字段到已打开的设置草稿；其他未保存编辑必须保留。
- Messenger 的后台状态观察只刷新联系人、身份和鱼鱼码等运行状态，不能覆盖正在编辑的名称与偏好草稿。
- 设置窗口仅在可见期间每秒刷新「计时快照」，用于更新倒数、暂停、响铃等即时状态，关闭时必须取消，避免隐藏窗口持续唤醒。声音/外观等未保存草稿必须与快照分离，刷新不得整份覆盖用户编辑。
- 性能面板的左右、垂直位置和与角色距离都写入 `AppConfig.performance`；新增字段必须通过默认配置合并兼容旧 `settings.json`。
- 建立鱼鱼身份会先在本地检查名称、HTTPS 中转地址和 16–256 字符设置密钥，再用真实建箱请求验证中转；设置密钥提交成功后立即清空。
- Messenger 偏好保存失败必须抛回设置页，设置页不得在服务回滚后继续显示「已保存」。
- 开机启动是跨系统注册与 `settings.json` 的两阶段操作：先更新系统，再保存配置；配置保存失败时必须回滚系统注册。
- 私钥不进入 SwiftUI 状态；身份有效性通过 Keychain 已加载资料和可生成鱼鱼码来确认。
- 鱼鱼码包含投递权限，设置页默认只能把「前 10 字符 + 省略号 + 后 6 字符」安全摘要放进 View/Accessibility tree；只有用户明确点击「显示完整鱼鱼码」后才展示全文，复制仍保持为独立明确动作。
- 鱼鱼码过短时摘要必须完全遮蔽，不能因首尾截取重叠而泄露全文；无可用码时不渲染码值。身份码改变或设置窗口从隐藏状态重新打开时必须恢复隐藏。
- 右键菜单已移除任务状态、Codex 与 Claude 长标题；「历史消息」使用紧凑的未读数字，「发消息…」不显示任务或会话状态。
- 配对、私钥、性能及开机启动等设置项不应占用右键菜单。

## 7. 闹钟与快速计时

- 四个内建闹钟 ID 保持为 `alarm-clock`、`alarm-clock-seafoam`、`alarm-clock-honey`、`alarm-clock-plum-night`；形象分别是珊瑚抱珍珠、扇贝海泡、蜂蜜方糖与月光水母，不能再用同一双铃轮廓只换色。旧时钟状态缺少 `alarmAccessoryID` 时安全回落到 `alarm-clock`。
- 闹钟与消息提示的可见图形使用柔和分层填色，不使用 `stroke`；运行时 SVG 与 `design/vi-assets` 设计源保持逐字一致。这是结构规则，最终美观仍需另行取得人工视觉检查批准。
- 重做素材必须保留既有 ID、slot、anchor、`viewBox="0 0 100 100"` 及 `alarm-clock-shaker` 响铃动画 class，避免外观更新破坏设置与动画。
- 闹钟位置以角色画面中心为 `(0, 0)`，配置范围为水平 `-240...240`、垂直 `-180...180`；运行时再按实际 PetView 画布与钟尺寸夹在可见边界内，因此可以移动到尽可能靠近四边而不会丢出窗口。普通饰品仍限制在 `-30...30`。
- 闹钟只允许 `size` 等比例缩放，解析器强制 `width = 1`、`height = 1`，捏鱼页不得显示宽度/高度滑杆；原生与共享 Electron 正规化及中心原点变换必须一致。
- 闹钟样式选择与位置调节都在「角色与动作 → 饰品」中；样式通过 ClockService 立即安全保存，位置/大小仍按角色和样式写入主设置草稿并随「应用」保存。捏鱼预览必须使用真实选中的闹钟 ID。
- 右键「闹钟与计时器…」打开独立 `ClockQuickWindowController`，与桌面鱼、右键快速计时及完整设置共用唯一 ClockService；快捷窗不得创建第二份状态或打开大型设置窗口。
- 未读提示不再使用红色胶囊。四个既有 ID 现分别是海葵举旗邮箱、月贝封信、鳐鱼飞信与海瓶漂流信；默认仍为 `message-mailbox`，数字直接印在邮旗、封印或信纸等物件内部。
- 消息素材重做时必须保留 `PetView.unreadCountRect` 的四个数字承载区与既有文字颜色契约；否则即使 SVG 本身合法，运行时未读数字仍可能落到错误位置或失去对比。
- 正式闹钟只要存在启用项便会让角色持钟。
- 快速计时剩余时间 `<= 15 分钟` 时持钟，超过 15 分钟不持钟；暂停、恢复、延长、取消及到期都必须重新计算。
- 当前四款闹钟与四款消息素材均为项目从零绘制的 CC0-1.0 SVG，不含 Apple 或第三方图形路径；来源与授权声明保存在各 pack 的 `SOURCE.md` 及 `design/vi-assets/LICENSE.md`。
- 所有闹钟、计时和稍后提醒变更使用「复制状态→写盘→提交内存」的交易顺序；写盘失败时内存状态不得假成已修改。
- 到点轮询只有在 ringing 状态保存成功后才发出声音和台词；保存失败时保留未到点状态重试，且同一失败周期只报错一次。
- `clock-state.json` 不安全或损坏时会延后上报，不再静默当成空闹钟列表。

## 8. 长时间运行与回滚

- `CalendarService`、`RoutineService` 和 `TaskMonitor` 必须具备幂等 `start`；`stop` 通过 run generation 使旧权限回调、电池轮询和后台任务结果失效。
- TaskMonitor 必须在进入后台队列前快照 provider 集合和标题隐私开关，不可在主线程修改 `Set` 时从后台同步读取。
- 作息与日历提醒的去重键使用 FIFO 有界历史；达到容量时只淘汰最旧键，不能 `removeAll` 导致当前提醒在 30–60 秒内重复。
- 整合插件与原生更新共用可恢复目录替换；新目录安装失败时恢复 backup，若恢复也失败必须显式报告双重失败。
- 更新安装失败时清理 `.installing` 临时应用；成功后 backup 清理失败刻意保留隐藏备份，因新版已在目标位置，不虚报「安装失败」。
- 版本比较支持 SemVer prerelease；正式 `2.3.0` 高于 `2.3.0-beta.1`，不可把无法解析的当前版本当成「已是最新」。
- 限制：外部 CLI 市场/插件命令可能在后续命令失败前已修改第三方工具状态；当前只能保证本地 managed integration 目录回滚，完整外部回滚需要 Codex/Claude CLI 提供可靠的反向操作。
- 限制：更新器的 `ditto` 和 `codesign` 验证仍是后台同步进程，没有超时上限；异常系统状态下可能使安装回调长时间不返回，后续应与 IntegrationManager 共用带超时的进程执行器。

## 9. 测试重点

- Messenger：单飞轮询、重复 ID 去重、未知信封处理、内存记录上限及状态通知。
- 串门：关闭、静音、封锁；水平/垂直游动、拖动、fling、fling 穿过鼠标及四边碰撞。
- 多屏：屏幕接缝、拔除屏幕、不同角色尺寸和 `0.65...1.5` 缩放。
- 布局：任务卡、性能面板、牵手栏、1–3 条双方气泡、闹钟和倒数的组合不重叠。
- 场景边缘：至少覆盖角色位于 visibleFrame 上、下、左、右精确边缘，timer+visit 并存、串门 companion、跨屏 local 坐标，以及透明控件间隙不拦截鼠标。
- 计时：`900001ms` 不持钟、`900000ms` 持钟，并覆盖暂停、恢复和延长跨阈值。
- 设置：旧窗口草稿不得覆盖右键菜单后的新值；倒数需要持续刷新。
- 设置安全：鱼鱼码默认摘要不得等于全文；覆盖空码、短码、明确 reveal、身份改变和窗口重开后的隐藏恢复。
- 互动：未读角标可命中，并能打开正确联系人会话和标记已读。
- 快捷传话：覆盖单击、双击、4 pt 拖动阈值、首次显示前定位、四边候选位、负坐标和异高多屏幕；隐藏的发消息窗口不得接收逐帧重定位。
- 持久化：时钟回滚、到点保存失败不提醒、Messenger 未落盘不确认、不安全状态文件拒绝。
- 生命周期：身份延后创建后启动轮询、重复 start 不重复 Timer、stop 后旧回调不回流。
- 回滚：目录替换失败恢复 backup 并清理 temporary，开机启动配置保存失败回滚系统注册。
- 视觉资源静态验证：闹钟／消息 SVG 可解析、无主动内容与外部引用、无可见描边、设计源和运行时逐字一致；这些检查不能替代人工视觉 QA。
- 语言：四包事件集合一致，中英文同角色新增事件计数对齐，原始台词保持逐字不动，条件只使用共享白名单。
- 表情：小草团只列出三个原生 face，水滴鱼不列出 `face-grass-*`；旧 face 语义映射、默认 calm、状态／对话／串门兼容解析及原生 SVG 节点切换都需回归。

## 10. 当前发布限制

- 本地开发包仍允许 ad-hoc 签名，但启动 Keychain 探测禁止交互，因此不会自动弹出电脑密码；这种构建不能验证更新后的稳定身份。
- 项目明确不购买 Apple Developer ID；正式 tag 与本地包都使用 ad-hoc 签名，不做 notarization，也不依赖 Apple/GitHub 签名 secrets。Release 页面和 README 必须如实标示这一点。
- GitHub Actions 必须分别构建 arm64/x64、验证准确架构并确认签名类型为 `adhoc`；不能把 ad-hoc 包描述成 Developer ID 或已公证安装包。
- ad-hoc 身份无法保证跨版本稳定；私钥读取只允许在用户明确点击解锁后发生，首次解锁或身份变化时仍可能出现系统授权。
- macOS 首次打开可能要求用户在“系统设置 → 隐私与安全性”中明确允许；项目不得自动执行 `xattr`、关闭 Gatekeeper、绕过完整性校验或降低更新校验。
- 一键更新依赖与芯片匹配的完整 ZIP、正确 SHA-256 和更新清单。
