# 水滴鱼项目经验与维护决策

更新日期：2026-08-05  
当前开发基线：`d020663` / `v2.3.0-beta.1`  
当前开发分支：`codex/scene-messenger-settings-refactor`

本文只记录已经从代码、测试或人工验证中确认的事实、约束和决策。尚未验证的猜测不得写成结论；每轮维护结束前应同步更新本文。

## 1. 维护规则

- 正式产品是 Swift/AppKit 原生应用，主代码位于 `native-appkit/Sources/BlobfishNative`。
- 仓库保留旧 Electron 实现用于资源、兼容逻辑及测试参考，不能在未核对引用关系时整目录删除。
- 修改必须从最新 `main` 建立 `codex/...` 分支，通过小步提交保留回滚点。
- 不用隐藏 UI、吞异常、写死结果或关闭校验来掩盖底层问题。
- 私钥、Token、证书和建箱密语不得写入仓库、日志或本文。
- 任何视觉检查、浏览器操作、耗时完整构建或非必要全量测试，开始前需取得维护者许可。本轮已取得相关许可，但仍应控制调用次数。

## 2. 角色与内容约束

### 水滴鱼

- 性格是委屈、疲惫、认命、轻微抱怨并偶尔关心。
- 台词通常较短，以「。」「……」收尾；避免过度卖萌、客服口吻、连续惊叹号及空泛鼓励。
- 常用深海、游不动、躺平、鱼鳍发酸等意象。
- 权威文字规范：`src/packs/languages/blobfish-zh-TW/style.json`。

### 小草团

- 项目正式名称是「小草团」。
- 性格是木讷、慢半拍、冷幽默、略委屈并偶尔关心。
- 使用风、根、叶、扎根、长大和开花等植物意象。
- 权威文字规范：`src/packs/languages/grass-buddy-zh-CN/style.json`。

## 3. 运动与屏幕边界

- `PetPanelController` 当前同时负责窗口、运动、拖动、惯性、边界、串门及部分展示状态，职责过多。
- 串门开始时会设置 `visitPaused = true` 并清除惯性；全局移动暂停条件包含 `visitPaused`。这是串门破坏水平、垂直游动及惯性的直接根因。
- 当前碰撞只使用主角色的 `petView.movementBounds`，不包含 `guestView`。双鱼靠近屏幕边缘时，访客可能越界。
- 正确边界模型应使用自己与访客角色可见身体的联合区域；任务卡、气泡、性能面板等附着 UI 不应参与物理碰撞。
- 靠近屏幕边缘时，附着 UI 应翻侧、压缩或换位，不能通过移动角色来迁就附着 UI。
- 拖动、fling、自动游动和屏幕碰撞必须由同一个运动状态模型控制，避免多份基线和坐标互相覆盖。

## 4. 桌面显示模块

- `PetView.drawOverlay()` 当前按固定顺序绘制倒数、性能面板、台词气泡、任务卡、闹钟卡、牵手栏和未读角标，没有统一避让。
- 倒数牌与牵手栏使用相近的底部区域；台词气泡与闹钟卡也会重叠。
- 性能面板位置按整个 `340×300` 画布计算，不以角色为锚点，因此可能离角色过远或与放大后的角色相交。
- 后续使用纯逻辑 `SceneLayoutCoordinator`：输入角色锚点、屏幕安全区、元素尺寸和优先级，输出不重叠矩形与气泡方向。
- 建议显示层级：角色与饰品、鱼别气泡、任务/闹钟提醒、性能/牵手状态、未读与可点击控件。
- 好友消息使用独立气泡堆栈，不与普通角色台词的 `SpeechQueue` 共用替换规则。
- 好友气泡最多同时显示三条；新消息靠近说话者，旧消息上移并逐级透明，每条消息有独立到期时间。
- 串门时，对方消息由访客鱼显示，自己发出的正文由自己的鱼显示。

## 5. 鱼鱼传话与串门

- 身份私钥、收件权限和好友资料保存在 Keychain；不得改为普通明文配置。
- 设置页可以提供安全导入、有效性和指纹状态，但不默认展示私钥原文。重建身份必须二次确认。
- `FishMessengerService.poll()` 当前没有单飞保护。轮询间隔为 8 秒而网络超时可达 15 秒，可能同时拉取同一批未确认消息。
- 收到消息时没有 message ID 去重；重叠轮询可能重复保存、播音和触发串门副作用。
- 未知发件人的信封当前不会加入确认列表，可能被中转站持续重新投递。
- 消息记录只在写盘时截断为 500 条，运行时数组没有上限。
- `createProfile` 与 `addContact` 成功后当前不会通知观察者，已打开的 UI 可能不刷新。
- 串门状态变更必须先检查 `blocked`、`muted` 和 `visitsEnabled`，不能先改变状态再由 UI 忽略。
- 配对、中转站、建箱密语、身份状态及鱼鱼码迁入设置页；右键菜单只保留打开独立聊天窗口的入口。
- 独立聊天窗口按联系人分组，收到消息靠左、发出消息靠右；未读角标点击后打开对应会话并标记已读。

## 6. 设置与右键菜单

- 当前设置窗口默认 `1100×760`，最小 `920×680`；侧栏宽 235，导航项高 50，共七个主栏目。
- 目标是紧凑而不拥挤的约 `820×600` 默认尺寸；最终尺寸需通过人工视觉检查确认。
- 消息历史从设置页移出；设置只保留账户、安全、配对、停留时间、声音和串门权限。
- 设置草稿当前只在控制器初始化时复制一次，控制器又会长期复用。关闭设置后从右键修改配置，再打开旧草稿整体 Apply，可能覆盖较新的配置。
- 设置保存应重新读取最新配置或使用字段级提交；打开窗口时必须刷新草稿和服务状态。
- 设置页的倒数目前不会跟随 `ClockService.onTick` 每秒刷新，需要可取消的观察机制。
- 右键菜单的任务状态、Codex 与 Claude 长标题会使菜单过宽，应整体移除。
- 配对、私钥、性能及开机启动等设置项不应占用右键菜单。

## 7. 闹钟与快速计时

- 现有 `alarm-clock` 是传统双铃 SVG，当前主色为灰绿/薄荷色，并已有进场、退场和响铃震动动画。
- 正式闹钟只要存在启用项便会让角色持钟。
- 快速计时当前只显示下方倒数牌，不会让角色持钟。
- 新规则：快速计时剩余时间 `<= 15 分钟` 时持钟，超过 15 分钟不持钟；暂停、恢复、延长、取消及到期都必须重新计算。
- 红色闹钟优先采用允许修改、商业使用及重新分发的 SVG；必须保存来源 URL、作者、授权版本、下载日期和许可证文本。

## 8. 测试重点

- Messenger：单飞轮询、重复 ID 去重、未知信封处理、内存记录上限及状态通知。
- 串门：关闭、静音、封锁；水平/垂直游动、拖动、fling 及四边碰撞。
- 多屏：屏幕接缝、拔除屏幕、不同角色尺寸和 `0.65...1.5` 缩放。
- 布局：任务卡、性能面板、牵手栏、1–3 条双方气泡、闹钟和倒数的组合不重叠。
- 计时：`900001ms` 不持钟、`900000ms` 持钟，并覆盖暂停、恢复和延长跨阈值。
- 设置：旧窗口草稿不得覆盖右键菜单后的新值；倒数需要持续刷新。
- 互动：未读角标可命中，并能打开正确联系人会话和标记已读。

## 9. 当前发布限制

- 当前仍使用 ad-hoc 签名，没有 Apple Developer ID 和公证。
- 不得为了简化安装而关闭 Gatekeeper、绕过完整性校验或降低更新校验。
- 一键更新依赖与芯片匹配的完整 ZIP、正确 SHA-256 和更新清单。
