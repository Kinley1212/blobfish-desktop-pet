# Codex hooks、问题面板与轻量接入（2026-09-12）

状态：macOS 原生 2.8.0-beta.1 发布候选。模拟协议、原生自检、独立 UI 预览与压力测试已验证；**尚未重启当前 Codex，未做真实桌面会话端到端验收**。因此发布为预发行，不取代稳定版。未替换桌面水滴鱼，Windows 未提交工作不混入本次发布。

## 维护者决策

- 自动审核不能冒充人工确认；拒绝把所有审批统一降级为“不提醒”。真实人工审批继续提醒。
- 本次展示问题正文、选项、多道问题，设置中可以独立关闭。
- 有条件接受专用启动器：额外 CPU、内存低才采用。不要自动退出正在工作的 Codex。
- 问题面板只预览，回答仍在原 Codex 任务；不代批、不改变审批策略。
- 项目签名仍为 ad-hoc；不要求 Developer ID 或公证。

## 核实的接入能力

1. PermissionRequest hook 只证明进入审批流程，不证明已交给人。公开输入没有该次审批 reviewer 字段，permission_mode 也不是 reviewer。不能读取全局配置猜每个任务的审核方式。
2. hooks 文档说明部分特殊工具可能退出默认 hook 路径，不能保证提问工具必然触发 hooks。
3. 本机 Homebrew CLI 为 0.142.0；桌面附带 CLI 为 0.153.0-alpha.5。按桌面附带版本核验，未升级 CLI。
4. 桌面主 App Server 采用 stdio，没有可直接附接的公开具名监听端点。不能启动第二个 server 冒充当前桌面的任务，也不能把 MCP 工具 IPC 当作 App Server。
5. 后续只读检查桌面随附实现，确认 CODEX_CLI_PATH 替换入口，且 macOS open --env 支持单次启动环境。这是**已核验的本机桌面实现能力，不是长期稳定的公开集成承诺**。
6. 本机 schema 确认 item/tool/requestUserInput 的 questions 数组、isBlocking、isSecret，以及 serverRequest/resolved。autoResolutionMs 已弃用，仅作缺少 isBlocking 时兼容判断。自动审核通知载荷标记 UNSTABLE，不依赖其内部结构。

## 组件与行为

- native/CodexObserver.swift：Swift 原生透明启动器。非 app-server 命令直接 exec 原 CLI；app-server 只增加一个观察进程，子进程 stdin/stderr 直连，stdout 原字节转发。不向 stdin 注入 RPC、不选择答案、不自动审批、不调用模型。
- CodexObservation.swift：只观察 turn 生命周期、真实审批请求、结构化问题及 resolved。不持久化代码、命令参数、工具输出或聊天历史。模型 delta 不进入状态归约/快照编码。
- CodexTaskProjection.swift：观察到的同 thread 状态优先于旧 hooks；未接入线程和其他提供方保留原 hooks 回退。自动审核保持运行，人工审批/阻塞问题才 waiting，异步问题继续运行。中断不冒充完成。
- TaskMonitor.swift / AppDelegate.swift：按请求独立提醒与去重，不依赖所有任务同时 waiting。关闭问题展示不关闭人工审批提醒。
- CodexQuestionWindowController.swift：300×340 pt 粉色信纸小面板，浅/深色适配，纵向只读选项、多题翻页、长文滚动、无选项说明。跟随鱼并限制屏幕边界，不主动激活 App、不抢键盘。关闭后的同一请求不被轮询重开；新请求可打开；回答、取消、结束后清理对应问题。
- “回 Codex 回答”使用本机已核验的 codex://threads/<threadID>，仅用户点击触发；失败会提示手动返回。
- 两个角色四份语言包各增加 9 句，共 36 句，对应单题、多题、边做边问；旧台词不变。

## 隐私与资源上限

- 设置“连接与隐私 → 显示 Codex 问题与选项”默认关闭。启用并应用后，仅后续收到的问题进入预览，不补读历史。
- 关闭并应用立即收起/释放面板；观察器下次设置检查（约 2 秒）清除正文、停止收集。人工审批元数据独立保留。
- isSecret 问题不预览、不落盘。原文按纯文本显示，不执行其内容。
- 快照位于本机 ~/Library/Application Support/BlobfishDesktopPet/codex-observations。**存在短时本地落盘缓存，并非“完全不落盘”。** 父目录需私有，目录 0700、文件 0600；拒绝符号链接/非当前用户文件，临时文件原子替换。
- 2 秒心跳，6 秒后不读取失联快照。正常退出删除自己的快照；宠物轮询回收超过 15 秒未更新且符合专用文件名/权限的遗留快照。不写产品消息历史或日志。
- 最多 64 个线程；每线程 32 个审批、32 个阻塞请求、16 个预览请求；每请求最多 12 题、每题 12 选项。正文总预算 64 KiB，快照最大 512 KiB，NDJSON 单行解析最大 1 MiB。超限正文省略，原协议字节仍转发，完整内容在 Codex 阅读。
- 状态变化即时发布；心跳不改变任务事件时间，避免每秒无意义刷新 UI。输出管道关闭时处理 SIGPIPE 并清理自己启动的 server。
- 无新增 npm 生产依赖，无模型/网络调用，无额外模型 token 成本；不更改信任、权限、认证和全局环境。

## 启用与回退

1. 自行退出已有水滴鱼，再打开本地测试包（保留单实例锁）。本轮未代替用户切换。
2. “设置 → 连接与隐私”开启 Codex 和问题选项并应用；“显示 Codex 专用启动器”可在 Finder 定位随包文件。
3. 等方便时保存工作、自行完全退出 Codex，再双击 LaunchCodexWithBlobfish.command。仍运行时启动器拒绝执行，不自动退出。
4. 启动器只为本次启动设置 CODEX_CLI_PATH 和真实 CLI 路径。退出后按普通方式打开 Codex即可停用观察器。关闭问题开关只停正文，不取消准确审批状态源。

本地试用包：native-appkit/.build/codex-question-test.LIbk95/水滴鱼.app。
开发启动器：native/build/LaunchCodexWithBlobfish.command，必须和同目录 blobfish-codex-observer 一起保留。

## 发布前压力测试与 Debug

- 原生自检扩展为 107/107：关闭设置时拒绝旧异步轮询结果，防止面板/状态短暂重新出现；重复结束或无关 resolved 不刷新结束时间；超过预览题数上限时仍保留阻塞状态；140 个旧快照先清理再限制有效文件数，避免缓存过多后永久失效。
- 翻题时重建滚动区域，避免下一题从上一题底部开始。管道关闭转为正常错误退出，不产生 Swift fatal-error 崩溃报告；测试确认其 server 子进程退出。
- 测试不再依赖本机预先编译的 native/build 产物，而是在私有临时目录构建，保证干净检出可执行；发布 CI 加入观察器压力测试、双架构/签名与启动器存在性检查。
- 100,000 个模型 delta + 8,000 个生命周期事件（64 个轮换任务），合计 108.04 MiB。完成后继续空闲 10 秒，检查无待处理问题、内存恢复、字节 SHA-256 一致。
- 首轮约 13.36 秒、峰值 RSS 46,096 KiB；逐字节扫描改为 memchr 批量扫描后曾暴露临时对象积压，RSS 87,184 KiB 超过 64 MiB 上限，测试如实失败。加入逐批 autoreleasepool 后复测通过，没有放宽阈值。
- 修复后的压力样本：约 7.11 秒完成突发，峰值 RSS 8,208 KiB（约 8.0 MiB），结束后 CPU 0.0%、RSS 4,352 KiB。持续灌满时采样峰值 CPU 95.4%（约一个核心），**不宣称满载下 CPU 为零**；这是极端突发吞吐测试，真实 Codex 长期占用仍需验收。
- 最终观察器测试 3/3 通过；10,000 delta 子测试由约 605 ms 降至 205 ms（机器调度会有波动，不作为保证）。
- 从精确暂存源码生成的干净副本运行全套 Node 测试，374/374 通过；未带入任何未提交 Windows 文件。2.8.0-beta.1 arm64 release 构建和独立本地包完成。

## 经验与一手依据

- Foundation read(upToCount: 64 KiB) 在管道延迟小消息，改用 availableData 后实时事件测试通过；不要为减少读取次数改回等待大块。
- 白名单事件才归约/编码；模型 delta 不做前后快照比较，避免高流量无谓开销。
- 没有原请求可信响应通道时，不做看似可提交的选项按钮；不能发新消息冒充原提问响应。
- “没有监听端点”只否定直接附接，不否定已授权的下次启动透明观察路径。
