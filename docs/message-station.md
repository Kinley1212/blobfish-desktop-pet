# macOS 迷你传话框 · 2026-09-08

## 设计与范围

- 用途：在其他应用旁快速传一句话，尽量少遮挡工作内容，不离开当前全屏工作空间。
- 用户最新偏好：极小优先，可以放弃上一版的信封装饰、竖排互动和贝壳小门。
- 方向取舍：单行输入条不适合既有多行输入；展开式聊天气泡会与桌面气泡重复；选择柔软、无描边的迷你便笺，保留淡粉底色与暖纸色。无需额外图片或依赖。
- 系统：SwiftUI + AppKit；正文 13 pt，收件人 12 pt，状态栏 10 pt，8 pt 外边距，6 pt 间距。颜色集中在 FishStationPalette，浅／深色纸面和墨色成对配置。
- 布局：默认 240×132 pt 内容区，比 360×356 pt 减少约 75%。顶部收件人及更多菜单高 22 pt，编辑区高 58 pt，底部状态与发送高 24 pt；原生标题栏另计，保留关闭和 Esc 行为。三个快捷互动及串门／回家位于更多菜单中。
- 来信：仅有当前收件人的来信时增加 40 pt 滚动区及 6 pt 间距，总内容区 240×178 pt；消息数量不再撑大窗口，所有已捕获来信均可滚动读取，不截成最后六条。
- 尺寸：FishComposeLayout 是视图和窗口的共同来源；控制器只在来信从无到有或从有到无时更新尺寸并重新避让屏幕边缘，不引入新轮询。
- 错误与发送状态：显示在底部，长文案可悬停读取全文，辅助功能标签保留全文；错误不替换正文，超限仍显示实际字节数并禁用发送。
- 输入：Enter 寄出，Command + Return 换行（2026-09-08 用户指定）；FishComposeEditor 用 NSTextView 在编辑器内部处理 Return 和数字键盘 Enter，Command 快捷键在 performKeyEquivalent 中处理，发送按钮不再抢占全窗口回车。组合文字交给系统输入法，长按回车不重复发送；保留 1,000 UTF-8 字节上限、发送防重入、失败草稿和异步草稿保护。
- 本轮不修改 Windows、角色美术、串门协议、身份／钥匙串或发布版本。历史消息窗口尺寸保持独立。

## 全屏窗口策略

旧传话入口使用普通 NSWindow 并显式激活整个应用，存在切回应用其他桌面窗口的风险。现改用 FishMessagePanel：构造时设置 nonactivatingPanel，可成为 key 但不能成为 main，配置 canJoinAllSpaces 与 fullScreenAuxiliary，显示前先计算鱼旁位置。历史窗口也使用该面板；其他设置与闹钟窗口不受影响。

Apple 对 nonactivatingPanel 的定义是“不激活所属应用的 NSPanel”。这支持本次窗口策略，但不能替代全屏、输入法与多屏现场验证：[Apple 文档](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel)。

## 待维护者批准的人工验收

1. 在其他应用的原生全屏空间，通过双击主鱼、右键传话、未读入口多次打开，确认首次和重开都不切回桌面。
2. 中文拼音候选确认不寄出；Enter 只发送一次，Command + Return 在光标处换行；长按 Enter 不重复发送，数字键盘 Enter 行为相同；Esc 和关闭按钮释放焦点并保留草稿。
3. 原应用继续保持全屏；两个屏幕分别全屏、左右负坐标与不同高度屏幕中，鱼旁面板可输入且在工作区内。
4. 在面板失去 key 时收到消息，不应被自动标记已读；重新聚焦后只读取当前联系人。
5. 浅／深色、中／英文、长联系人名、多条长来信、超过字节限制和网络失败：文字可读、控件不重叠、正文可滚动；长状态悬停显示全文。
6. 更多菜单能发送三个配置的互动并串门／回家；串门处理时不能重复触发，失败保持原状态；回家只结束当前串门，拖甩和屏幕碰撞不因面板尺寸改变。
7. 无来信时内容区 240×132 pt，有来信时 240×178 pt；切换收件人、面板失焦和重新聚焦后的尺寸始终一致，屏幕四边不越界，编辑区不被来信挤压。

通过现场验收前不得写成“全屏、输入法和视觉完全验证”。
