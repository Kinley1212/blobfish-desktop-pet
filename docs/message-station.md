# macOS 随身小邮局 · 2026-09-04

## 设计与范围

- 用途：在其他应用旁快速写信，不离开当前全屏工作空间。
- 方向：柔软、无描边的粉色信封与露出的信纸；与水滴鱼现有角色一致。不生成额外位图，不新增依赖。
- 系统：SwiftUI + AppKit；系统圆角标题字与可读的正文。颜色集中在 FishStationPalette，浅／深色分别配对纸面、信封和墨色。
- 布局：360×356 pt 内容区域；左侧写信／来信，右侧 86 pt 竖排快捷互动，底部贝壳小门进入串门或回家。发送是信封上的文字邮票，不与互动按钮混放。
- 输入：Enter 换行，Command + Return 寄出；保留 1,000 UTF-8 字节上限、发送防重入、失败草稿和异步草稿保护。
- 本轮不修改 Windows、角色美术、串门协议、身份／钥匙串或发布版本。

## 全屏窗口策略

旧传话入口使用普通 NSWindow 并显式激活整个应用，存在切回应用其他桌面窗口的风险。现改用 FishMessagePanel：构造时设置 nonactivatingPanel，可成为 key 但不能成为 main，配置 canJoinAllSpaces 与 fullScreenAuxiliary，显示前先计算鱼旁位置。历史窗口也使用该面板；其他设置与闹钟窗口不受影响。

Apple 对 nonactivatingPanel 的定义是“不激活所属应用的 NSPanel”。这支持本次窗口策略，但不能替代全屏、输入法与多屏现场验证：[Apple 文档](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel)。

- 原生 self-check：多行加密往返、新草稿保护、新窗口尺寸在负坐标屏幕四边的放置，以及既有运动／串门／消息回归。
- test/native-message-station.test.js：面板创建标志、无整应用激活入口、key 状态已读门控、多行／IME guard、竖排互动、限定来信高度与浅深颜色配对。
- 没有启动桌宠、截图、渲染预览或做视觉检查；结构测试不证明视觉美观或 WindowServer 行为已验收。

## 待维护者批准的人工验收

1. 在其他应用的原生全屏空间，通过双击主鱼、右键传话、未读入口多次打开，确认首次和重开都不切回桌面。
2. 中文拼音候选确认不寄出；Enter 换行，Command + Return 只发送一次；Esc 和关闭按钮释放焦点并保留草稿。
3. 原应用继续保持全屏；两个屏幕分别全屏、左右负坐标与不同高度屏幕中，鱼旁面板可输入且在工作区内。
4. 在面板失去 key 时收到消息，不应被自动标记已读；重新聚焦后只读取当前联系人。
5. 浅／深色、中／英文、长联系人名、六条长来信、超过字节限制和网络失败：文字可读、控件不重叠、正文可滚动。
6. 互动按钮竖排；串门处理时不能重复触发，失败保持原状态；回家只结束当前串门，拖甩和屏幕碰撞不因面板尺寸改变。

通过现场验收前不得写成“全屏、输入法和视觉完全验证”。
