# 鱼鱼传话（原生版）

## 问题与目标

水滴鱼主要由少量彼此认识的朋友使用。鱼鱼传话让桌宠替主人送一句话，并在朋友桌面上用气泡说出来；它不是完整聊天软件，也不要求注册公共账号。

首版目标：两位用户能在 1 分钟内完成双向配对；在线消息通常在 15 秒内出现；中转服务无法读取正文；Intel 与 Apple Silicon 行为一致。

## 首版范围（P0）

- 每台设备创建独立收件箱与 Curve25519 身份密钥。
- 双方各分享一次 `fish1_…` 鱼鱼码，建立双向好友关系。
- 发送最多 1000 UTF-8 字节的文字；使用 Curve25519、HKDF-SHA256 与 ChaChaPoly 端到端加密。
- 中转服务最多保存 100 条密文，30 天过期；客户端确认后删除。
- 收到消息时由桌宠播放反应，并显示发送者名字和正文。
- 私钥、收件令牌与好友信息保存在 macOS Keychain，仅限当前设备。
- 好友模型预留静音与封锁状态；首版设置界面接入后开放控制。

## 非目标

- 不做公共好友搜索、群聊、图片、文件、语音或跨设备聊天记录同步。
- 不把鱼鱼码当作公开用户名；它含投递权限，只应私下分享。
- 中转服务不负责恢复私钥。重装或更换电脑后需要重新配对。
- 首版不承诺流量分析匿名性：服务仍会看到请求时间、IP 与密文大小。

## 核心流程

1. 用户在菜单栏选择“鱼鱼配对”，填写显示名、共同的 HTTPS 中转地址和部署时设置的建箱密语。
2. App 创建收件箱，将私钥与收件权限写入 Keychain。
3. 双方交换鱼鱼码并各自导入一次。
4. 发送方在本机加密正文，只把密文投递到朋友收件箱。
5. 接收方每 8 秒检查一次，验证发送者公开密钥后解密、展示并确认删除。

## 安全边界

- 中转数据库只有令牌哈希和加密信封，没有设备私钥或消息明文。
- 创建收件箱需要部署者设置的 `SETUP_SECRET`，避免公开服务被任意建箱滥用；该密语不保存到客户端。
- 客户端只连接鱼鱼码内同一个 HTTPS 中转站，并限制码、正文、响应和信封大小。
- 未配对发送者的信封不会解密；被封锁好友的消息会丢弃。
- 鱼鱼码泄漏者可以向对应收件箱投递垃圾密文，但不能读取消息或伪造已配对好友的可解密正文。

## 验收标准

- Given 双方已互相导入鱼鱼码，When 一方发送文字，Then 另一方的鱼在轮询周期内用气泡显示原文。
- Given 中转数据库被读取，Then 攻击者只能获得密文和公开密钥。
- Given 信封被修改或来自陌生密钥，Then 客户端不展示正文。
- Given 接收方离线少于 30 天，Then 再上线后仍能收到暂存消息。
- Given App 运行于 macOS 13+ 的 x86_64 或 arm64，Then 配对、收发和更新选择逻辑一致。

## 后续（P1/P2）

- 设置页好友管理、静音、封锁、解除配对和未读历史。
- 点击气泡直接回复、已送达／已读回执、传话专属游动动画。
- 多设备密钥迁移、推送通知、短配对码或二维码。
