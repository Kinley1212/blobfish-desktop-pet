# 串门等待与开门出场 · 2026-09-14

## 交互与视觉约定

- 目的：区分“邀请投递成功”与“对方实际响应”，不再先展示缓存鱼鱼再因离线消失。
- 风格（2026-09-16 更新）：沿用水滴鱼无描边、柔和粉色的玩具感。右上角圆形电话图标短促震动后停顿；奶油粉色小门位于侧上方，鱼鱼由远及近、由小变大向我方鱼鱼靠近，缓慢上下起伏，到位后门才淡出。使用原生绘制及系统电话图标，不新增图片依赖。
- 发起方：点击 → 等待响应 → 收到匹配的接受回复 → 约 2.4 秒开门、靠近、站稳、门淡出 → 串门中。等待最多 40 秒；网络投递失败、取消、关闭串门或屏蔽/静音好友会清掉等待状态。
- 邀请已投递但尚未接通时，原串门按钮变为取消呼叫。投递本身进行中沿用发送互斥，不重复发邀请。
- 电话只在等待时使用独立 CALayer 的旋转关键帧动画，周期 1.35 秒，含约半周期停顿；不触发整块 overlay 的逐帧重绘。取消、接通、超时或停止控制器会停止震动。减少动态效果时保持静态电话、跳过出场。
- 出场使用现有 movement display link：绘制比例从 28% 增大到 100%，斜向偏移逐渐归零；走路起伏幅度不超过 4 点且两端平滑归零，随后衔接原有游动。完成靠近后保留短暂停顿，最后才淡出门。不改变角色 movementBounds、不修改甩动速度。
- 门的位置与最终落点独立，按当前可见屏幕限制位置；只跟随整个鱼鱼场景，不跟随访客的靠近偏移。碰撞判定仍使用固定最终落点。
- 动画只用于已确认的访客；新来信气泡、拖动和现有互动继续独立工作。

## 状态与兼容边界

- `FishPendingVisit` 只存内存。请求 ID 和好友 ID 匹配后才能接受回应；迟到或不匹配的回应不能触发出场。
- 新版 `visitAccept` 使用已有 `replyTo` 字段回传邀请 ID，协议结构不变。旧版未回传 ID 时回退到当前等待好友和回复时间验证，因此旧版互通依赖两台设备时钟大致同步，不能保证与新版相同的严格请求关联。
- 排队超过 40 秒的旧邀请不会在重新上线后突然触发串门。邀请允许最多 5 秒的未来时钟偏差。
- 接收方收到新鲜且验证通过的邀请后沿用自动接受；发起方必须收到回应才显示访客。中转上传成功不再激活发送方；晚完成的接受发送也不会重新激活已结束串门。
- 接收批次落盘失败时恢复等待状态及存活时间；超时回调携带请求 ID，旧回调不能清除新请求。
