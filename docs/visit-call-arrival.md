# 串门等待与开门出场 · 2026-09-14

## 交互与视觉约定

- 目的：区分“邀请投递成功”与“对方实际响应”，不再先展示缓存鱼鱼再因离线消失。
- 风格：沿用水滴鱼无描边、柔和粉色的玩具感。右上角小电话表示等待；奶油粉色小门打开，鱼鱼从小到大淡入，门退出。使用原生绘制及系统电话图标，不新增图片依赖。
- 发起方：点击 → 等待响应 → 收到匹配的接受回复 → 约 1.25 秒开门出场 → 串门中。等待最多 40 秒；网络投递失败、取消、关闭串门或屏蔽/静音好友会清掉等待状态。
- 邀请已投递但尚未接通时，原串门按钮变为取消呼叫。投递本身进行中沿用发送互斥，不重复发邀请。
- 电话无常驻动画；出场使用现有 movement display link，不创建动画计时器、不改变角色 movementBounds、不修改甩动速度。减少动态效果时跳过出场动画。
- 动画只用于已确认的访客；新来信气泡、拖动和现有互动继续独立工作。

## 状态与兼容边界

- `FishPendingVisit` 只存内存。请求 ID 和好友 ID 匹配后才能接受回应；迟到或不匹配的回应不能触发出场。
- 新版 `visitAccept` 使用已有 `replyTo` 字段回传邀请 ID，协议结构不变。旧版未回传 ID 时回退到当前等待好友和回复时间验证，因此旧版互通依赖两台设备时钟大致同步，不能保证与新版相同的严格请求关联。
- 排队超过 40 秒的旧邀请不会在重新上线后突然触发串门。邀请允许最多 5 秒的未来时钟偏差。
- 接收方收到新鲜且验证通过的邀请后沿用自动接受；发起方必须收到回应才显示访客。中转上传成功不再激活发送方；晚完成的接受发送也不会重新激活已结束串门。
- 接收批次落盘失败时恢复等待状态及存活时间；超时回调携带请求 ID，旧回调不能清除新请求。
