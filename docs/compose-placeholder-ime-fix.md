# 传话输入框占位文字与中文组字 · 2026-09-12

## 原因与修复

SwiftUI 外层占位文字只判断 `model.draft.isEmpty`，但 NSTextView 的输入法 marked text 可能早于绑定更新出现，导致“说点什么…”叠在正在组字的文字上。聊天记录回复框使用同一模式。

占位文字改由 `FishComposeTextView` 绘制，仅当原生字符串为空且没有 marked text 时显示。普通编辑、组字更新、取消组字及程序清空草稿均请求重绘。两个入口复用，不新增计时器或状态绑定；保留输入法确认候选、回车发送、Command-Return 换行的既有规则。

## 验证

- 原生自检 112/112 通过；使用真实 NSTextView API 测试拼音组字、确认候选、删除、取消、解除 marked text、空白与恢复草稿。
- 消息窗口专项 Node 检查 5/5 通过，覆盖两个入口、组字发送保护及重绘触发路径。
- 第一轮新增测试误将无窗口视图的 `needsDisplay` 当作可靠重绘断言。实测组字与隐藏状态正确，但 AppKit 会丢弃离屏视图的绘制失效标记；改为原生状态行为测试配合重绘路径源码检查，不声称通过视觉验收。
